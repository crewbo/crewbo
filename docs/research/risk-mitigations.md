# Hooks, heterogeneity and governance beat the five risks

All five risks can be overcome, and the same design choice answers most of them: make the product the **cross-vendor, cross-machine, multi-human claim and intent layer** that lives in every agent's native hook system, with MCP as the query surface rather than the delivery mechanism. Hooks solve the pull problem because every target agent (Claude Code, Codex, Cursor, Gemini CLI, Antigravity, Copilot, VS Code, OpenCode) now exposes a PreToolUse-style gate that can deny an edit to a claimed file and explain why, so an agent that never calls your MCP tool still hits team state at the moment it matters. Vendor entry is survivable because every native coordination primitive shipped so far is scoped to one account or one vendor's team plan, and the problem itself is worst across vendors: cross-agent PRs conflict at **41.7%** versus **19.8%** within a single agent. Conductor's multiplayer is human presence over Mac-only, Conductor-hosted sandboxes with no documented conflict detection, which leaves "code stays on members' machines, all three OSes, self-hostable control plane" unoccupied. The maturity gap closes by assembling a Tier-1 Go MCP SDK, `git merge-tree`, and Centrifugo rather than writing infrastructure. Monetization should follow GitLab, n8n and Coder: keep team sync free and charge the team lead for policy, audit and analytics of agent actions, which is exactly what Vibe Kanban failed to put behind its paywall.

## Risk 1: hooks turn a pull protocol into push and enforcement

MCP will not rescue you. The 2026-07-28 revision made the protocol stateless, replaced resource subscriptions with an opt-in `subscriptions/listen` stream, and replaced server-initiated requests with Multi Round-Trip Requests so a server "can no longer start an interaction unprompted" ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)). Even where change notifications exist, clients ignore them: Claude Code **silently drops `resources/updated`**, and the issue was closed "not planned" in May 2026 ([claudeissues #47823](https://claudeissues.com/issue/47823-mcp-notifications-resources-updated-not-handled-per-spec)). Rules files are no substitute. In a 1,650-session factorial study, Claude Code followed a simple always-apply rule only **54.9% to 82.0%** of the time depending on model, compliance decayed with each additional step, and the authors explicitly recommend PreToolUse, PostToolUse and Stop hooks instead ([arXiv 2605.10039](https://arxiv.org/abs/2605.10039)).

| Option | Reach | Timing | Weakness |
|---|---|---|---|
| MCP tools plus AGENTS.md instructions | All agents | Only when the agent chooses | 18 to 45% of rule applications skipped |
| Piggyback team deltas on every MCP tool result | All agents | Next call to your tools | Still pull |
| Native push (Claude channels, Claude messaging socket, Codex App Server) | Claude, Codex only | Mid-turn | Channels are research preview; Codex needs App Server ownership |
| Per-agent hooks: digest injection plus PreToolUse deny | All eight hook systems | Session start, each prompt, each write | Per-agent adapters; shell edits bypass file-tool matchers |
| ACP proxy | ACP agents, Antigravity absent | Every prompt | Users must launch agents through your proxy |
| Filesystem watcher plus git pre-commit | Universal | After the fact | Detects, cannot prevent wasted work |

**Recommendation: a four-layer stack with hooks as the spine.** Inject a compact team digest as `additionalContext` at session start and on each prompt (Claude `UserPromptSubmit`, Gemini `BeforeAgent`, Antigravity `PreInvocation` `injectSteps`), and deny writes to claimed paths at PreToolUse with a reason string such as "src/auth.ts claimed by Priya's agent, task #12", which makes the denial itself the push ([Claude Code hooks](https://code.claude.com/docs/en/hooks); [Codex hooks](https://learn.chatgpt.com/docs/hooks); [Cursor hooks](https://cursor.com/docs/agent/hooks); [Antigravity hooks](https://www.antigravity.google/docs/hooks?tab=ide)). Layer native push on top where it is stable: Claude Code's cross-session messaging is **on by default since v2.1.224** and exposes `CLAUDE_CODE_MESSAGING_SOCKET` and a token to hooks and child processes, and an idle receiving session "starts a new turn with the message" ([cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)). That is a better dependency than channels, which require a dev flag, claude.ai auth, and break on protocol 2026-07-28 without a legacy override ([Claude Code MCP docs](https://code.claude.com/docs/en/mcp)). Backstop with a watcher and a pre-commit check in the git-kura style ([git-kura](https://pkg.go.dev/github.com/tooppoo/git-kura)). The research supports pairing state with enforcement: in synthetic experiments, locks alone cut duplicate work from 0.78 to 0.64, while locks plus shared state drove it to **0.00** and tripled goodput ([arXiv 2606.19616](https://arxiv.org/abs/2606.19616)).

**Residual risk.** Hooks are "a useful guardrail, not a complete enforcement boundary" by OpenAI's own description, and agents can write via `sed -i` or `cat >`, so the PreToolUse handler must parse shell commands too ([Codex hooks](https://learn.chatgpt.com/docs/hooks)). Coverage is uneven: Cursor's `beforeSubmitPrompt` cannot inject context, Copilot drops `userPromptSubmitted` output from command hooks, and Antigravity's PreToolUse cannot modify input. Hook schemas are not portable and change per release, so the adapter generator is permanent maintenance. Whether an external process (your daemon, not a child of the session) can post to a Claude socket without being held is untested and should be the first prototype.

## Risk 2: vendors coordinate their own estate, never a competitor's agent

Anthropic is the most dangerous vendor because it has already built almost every primitive. Agent Teams have a mailbox, a dependency-aware task list and file-locked claiming; cross-session messaging now relays to your sessions on other machines through Anthropic servers; and `isolatePeerMachines` exists in shipped docs ([agent teams](https://code.claude.com/docs/en/agent-teams); [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)). But every one of these is **scoped to one user account**: Projects "belong to one user" and are unavailable on Team and Enterprise, shared cloud sessions are read-only and not realtime, and cross-machine features refuse API keys, Bedrock, Vertex and Foundry ([Projects](https://code.claude.com/docs/en/claude-projects); [cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)). Cursor is the closest on the multi-human axis with team-owned shareable agents, Team Followups and Enterprise team pools, all inside one Cursor team ([Cursor changelog](https://cursor.com/changelog)). GitHub Agent HQ is genuinely cross-vendor but async and PR-centric ([ChannelLife](https://channellife.news/story/github-adds-claude-codex-agents-to-unified-ai-hub)).

| Option | Survives Anthropic shipping org-scoped teams? | Cost |
|---|---|---|
| Single-vendor bridge ("Agent Teams across machines") | No, a Growl or f.lux outcome | Low |
| Compete head-on with vendor team features | No, distribution loses | High |
| Neutral layer that ingests vendor primitives as data sources | Yes | Adapter maintenance |
| Publish an open team-state spec and be its reference implementation | Partly; depends on adoption | Spec work, governance |
| Integrate with Agent HQ, Linear, Slack rather than replace them | Yes | Low |

**Recommendation: be Datadog to their CloudWatch.** Treat each vendor's native team feature as another input, mirroring Claude team tasks and messages into the shared cross-vendor state through documented hooks (`TaskCreated`, `TaskCompleted`, `TeammateIdle`) and sockets, not the `~/.claude/teams` files Anthropic warns are overwritten ([agent teams](https://code.claude.com/docs/en/agent-teams)). Concentrate value where vendors structurally will not go: mixed-vendor teams, API-key and BYO-model users, self-hosted or LAN-only operation, and a durable team record. The precedent holds: CloudWatch "monitors only AWS resources" while Datadog spans clouds ([SigNoz](https://signoz.io/blog/datadog-vs-cloudwatch)), and IBM paid **$6.4B** for HashiCorp despite every cloud having native IaC ([IBM](https://newsroom.ibm.com/2025-02-27-ibm-completes-acquisition-of-hashicorp,-creates-comprehensive,-end-to-end-hybrid-cloud-platform)). The cautionary list is equally clear: Konfabulator, Growl and f.lux died because their entire value was one platform's missing checkbox ([How-To Geek](https://www.howtogeek.com/297651/what-does-it-mean-when-a-company-sherlocks-an-app)). Publishing the claim and intent schema as an open, versioned spec is worth doing cheaply; no AAIF project covers multi-human shared work state, and ACP grew from one company's spec to a JetBrains-co-stewarded registry without a foundation ([Ry Walker](https://rywalker.com/research/zed-agent-client-protocol)). Treat donation to AAIF as an aspiration, not a plan.

**Residual risk.** Single-vendor teams, the majority today, will default to their vendor once org-scoped features ship; the feature request for distributed Agent Teams across machines is already public ([GitHub #79507](https://github.com/anthropics/claude-code/issues/79507)). Your addressable market narrows to heterogeneous teams, which is why "distinct agent vendors per workspace" belongs among your core metrics. A vendor could also restrict hook or socket access, though both are documented and actively expanded.

## Risk 3: Conductor sells cloud presence, the open lane is local claims

Conductor is well funded (**$24M raised**, about six people) and moving fast, but its multiplayer is narrow ([RuntimeWire](https://runtimewire.com/article/conductor-launches-multiplayer-cloud-workspaces-coding-agents); [Vercel](https://vercel.com/customers/how-conductor-moved-parallel-coding-agents-from-the-laptop-to-the-cloud-with-vercel-sandbox)). Every team feature lives in a Conductor-hosted Vercel sandbox in us-east-1, the desktop client is **Mac only**, self-hosting is "in development", and collaboration means shared workspaces, presence, follow and reassign ([Conductor Cloud docs](https://www.conductor.build/docs/cloud-beta); [pricing](https://conductor.build/pricing)). No agent-to-agent overlap or conflict detection is documented. Its enterprise privacy mode blocks cloud workspaces, so privacy-sensitive orgs lose multiplayer entirely ([changelog 0.77.0](https://www.conductor.build/changelog/0.77.0-early-access-multiplayer-api-background-tasks-performance)). Across the field, no product combines multi-human coordination, local execution, Windows plus macOS plus Linux, and a self-hostable control plane: Paseo is cross-OS and self-hosted but single-user-centric, Superset has no Windows, and Cursor and Codex keep the agent loop in their cloud ([Paseo](https://paseo.sh/docs/alternatives/conductor.md); [Superset](https://superset.sh/compare/conductor-alternative); [AiCybr](https://aicybr.com/blog/cursor-self-hosted-machines-cloud-agents)).

| Option | Overlap with Conductor | Evidence of need |
|---|---|---|
| Cloud sandboxes with multiplayer | Direct; outspent | Weak for you |
| Another single-user parallel-agent desktop | Crowded (Paseo, Emdash, Nimbalyst, Claude Squad) | Saturated |
| Cross-machine claim and intent coordination, local execution, self-host | None today | 41.7% cross-agent conflict rate; Mac-only the top reason users leave Conductor |
| Team-lead dispatch to teammates' local agents | Partial (Conductor reassign is cloud-only) | Inferred |

**Recommendation: own semantic coordination across machines, not presence.** The pain is quantified: across 33,596 agent PRs, replayed merges conflict at **41.7% cross-agent** versus 19.8% intra-agent, which the authors attribute to agents having "no protocol to see each other's branches or claim files" ([Vaughan summary of arXiv 2607.04697](https://codex.danielvaughan.com/2026/07/28/agent-pr-merge-conflicts-concurrent-coding-agents-codex-cli-worktree-isolation-coordination-defence/)). Lead with intent claims plus `merge-tree` overlap prediction across teammates' machines, team-lead dispatch, and first-class Windows and Linux (Omarchy via AUR), and let Conductor be the Mac cloud option. The closest technical threat is **Foremerge**, an Apache-2.0 Rust tool with typed intent scopes, leases and an 18-tool MCP surface on all three OSes, which is single-machine today with multi-machine "on the roadmap" ([EveryDev](https://www.everydev.ai/tools/foremerge/llms.txt)). Interoperate with it or ship cross-machine first; do not ignore it.

**Residual risk.** Conductor's self-hosted cloud will close the privacy gap for Mac teams, and Foremerge going multi-machine would erase the technical lead in one release. The evidence that users leave Conductor over platform comes from a competitor's blog ([Nimbalyst](https://nimbalyst.com/blog/best-conductor-alternatives-2026/)), and no organic complaints about Conductor Cloud pricing or privacy were found, so demand for your exact intersection remains inferred.

## Risk 4: a solo builder closes the gap by assembling, not inventing

The category proves one person can ship credibly: Paseo reached about **20.2k stars** "built by one person", with 118 releases in roughly eight months ([Paseo repo](https://github.com/getpaseo/paseo); [Ry Walker](https://rywalker.com/research/paseo)). The trap is building infrastructure that already exists. The official Go MCP SDK is Tier 1, at v1.8.0 (14 Sep 2026) with full 2026-07-28 support ([go-sdk releases](https://github.com/modelcontextprotocol/go-sdk/releases)). go-git cannot merge (fast-forward only, no `merge-tree`), but `git merge-tree --write-tree --name-only -z --stdin` batch-predicts conflicts without touching the working tree, with exit code 1 signalling conflicts ([go-git compatibility](https://github.com/go-git/go-git/blob/main/COMPATIBILITY.md); [git docs](https://git-scm.com/docs/git-merge-tree)). Centrifugo (Apache-2.0, Go) provides presence and history recovery after reconnect, which raw NATS lacks ([Centrifugo comparisons](https://centrifugal.dev/docs/getting-started/comparisons)).

| Component | Option A | Option B | Pick |
|---|---|---|---|
| MCP | Go SDK (Tier 1) | Hand-rolled | Go SDK |
| Conflict prediction | go-git | Shell out to system git 2.38+ | System git |
| Sync server | Centrifugo plus Postgres/SQLite | PocketBase (pre-1.0, churn risk) | Centrifugo |
| UI | Tauri or Electron desktop | VS Code extension plus daemon-served web dashboard | Extension plus web |
| File events | fsnotify (no recursion, no FSEvents) | Hook-time `git status --porcelain -z` | Hook-time git, fsnotify as hint |
| Windows signing | OV cert ($150 to $300/yr) | SignPath Foundation (free for OSI repos) | SignPath |

**Recommendation: cut scope to daemon, hook adapters, sync server, and extension; defer the native desktop app.** Every desktop shell is another UI to maintain, and VS Code APIs already cover file decorations, CodeLens and comment threads ([VS Code API](https://code.visualstudio.com/api/references/vscode-api)). Mine Clash and git-kura as reference designs and Vibe Kanban's Apache-2.0 worktree code as owned fork material, since the upstream is sunsetting ([Vibe Kanban repo](https://github.com/BloopAI/vibe-kanban)). Prioritize the cross-platform landmines the notes surfaced: Azure Artifact Signing **excludes Indian individuals**, so SignPath is the realistic free path ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options); [Zenn](https://zenn.dev/shm_7ec/articles/signpath-oss-code-signing?locale=en)); Windows MAX_PATH breaks nested worktrees unless the daemon sets `core.longpaths` and keeps worktrees short ([Andrew Lock](https://andrewlock.net/fixing-max_path-issues-in-gitlab)); and Cursor's Open VSX mirror has stalled new extensions, so ship a sideloadable `.vsix` ([Cursor forum](https://forum.cursor.com/t/extension-published-recently-on-open-vsx-will-not-install-in-ide/151975)). GoReleaser covers AUR, Homebrew, Winget and Scoop from one config ([GoReleaser](https://goreleaser.com/customization/publish/aur/)). For correctness, copy the deterministic-simulation pattern at student scale: abstract time, network and git behind interfaces, replay recorded hook payloads as fake agents, and assert invariants such as "no two agents hold overlapping claims". WarpStream's invariant-driven simulation caught in **233 seconds** a race that tens of thousands of hours of race-detector CI missed ([WarpStream](https://www.warpstream.com/blog/deterministic-simulation-testing-for-our-entire-saas)).

**Residual risk.** The breadth is still large: eight hook schemas, three OSes, an extension in several VS Code forks, and a server. Bus factor is one, and hook formats churn monthly. Exams and coursework will compete for the release cadence that made Paseo work. macOS notarization cost was not verified in the notes. Mitigate by launching with two agents (Claude Code and Codex, which have the richest hooks and real push) and adding the rest only behind the adapter interface.

## Risk 5: charge the team lead for governance, not ICs for sync

Vibe Kanban did not die from lack of users. It charged **$30/user/month** for shared kanban, issues and org sync, made that paid tier itself open source and self-hostable, and shut the cloud down about 9.5 weeks later because "the vast majority are free users" ([VK Cloud launch](https://vibekanban.com/blog/introducing-vibe-kanban-cloud); [shutdown](https://vibekanban.com/blog/shutdown)). Nothing it charged for was manager-only, compliance-only or hosted-only, and it overlapped with Linear and GitHub Issues. The companies that convert gate by buyer: GitLab puts merge requests free and MR approvals paid ([GitLab handbook](https://handbook.gitlab.com/handbook/company/pricing)); n8n sells enterprise licenses once "several teams depend on those workflows" ([Sacra](https://sacra.com/chat/h/2480cb5d-24b9-46d4-913a-2f66142220a2/)); Coder gates RBAC, audit logs and **agent count caps** ([Coder pricing](https://coder.com/pricing.md)).

| Model | Evidence | Fit |
|---|---|---|
| Sponsorship only | Paseo, hobby-scale | Not a business |
| Hosted relay or sync per seat | Paseo gives its relay away free; Tailscale relays are cheap | Weak moat alone |
| Paid team sync (Vibe Kanban model) | Failed in 9.5 weeks | Avoid |
| Open core by buyer: free sync, paid policy, audit, analytics, SSO | GitLab, n8n, Coder | Strong |
| Event and university licenses | No evidence found | Acquisition channel, test cheaply |

**Recommendation: buyer-based open core with a split license, priced in the Linear and Tailscale band.** Keep the MCP server, hook adapters and daemon under Apache-2.0 so agent vendors and plugin authors adopt them freely, put the sync server under AGPL or FSL, and keep enterprise features in a commercial directory. FSL converts to Apache after two years and blocks only competing use ([fsl.software](https://fsl.software/)). Free covers small teams, self-hosting and BYO agents; a Team tier around **$8 to $20/user/month** adds the team-lead dashboard (dispatch history, throughput, conflicts prevented), path-level policy over which agent may touch what, and an audit log of agent actions; Enterprise adds SSO, SCIM, retention and HA. That band is defensible because buyers already pay $20 to $125/seat for Claude Team or Cursor, while Linear's Business tier is $16 and Tailscale Premium $18 ([Claude pricing](https://claude.com/pricing); [Linear pricing](https://linear.app/pricing); [Toolradar Tailscale](https://toolradar.com/tools/tailscale/pricing)). Draw the free and paid line at launch: Mattermost's late re-gating of message history provoked heavy backlash ([GIGAZINE](https://gigazine.net/gsc_news/en/20251226-mattermost-message-limit)). Use hackathons and universities as distribution, which fits the founder's position as an organizer and the Zed and GitHub student playbooks ([Zed docs](https://zed.dev/docs/account/plans-and-pricing.html)), but do not count on them as revenue; no evidence of organizer willingness to pay was found.

**Residual risk.** No agent-orchestration company has published team-tier conversion data, and the dev-tool freemium benchmarks of 1 to 5% are secondary and unsourced ([Monetizely](https://www.getmonetizely.com/articles/whats-the-right-ratio-of-free-to-paid-users-in-developer-saas)). Governance buyers mean enterprise sales, the exact path Bloop's founder walked away from. Indian price sensitivity is real but the PPP evidence is weak, so a flat per-team price with UPI-friendly annual billing is safer than deep per-seat discounts. Gate the paid launch on leading indicators rather than stars: workspaces with three or more weekly active humans, cross-user dispatches, conflicts prevented, and inbound SSO or audit requests.

## Conclusion

The five risks collapse into one strategic bet: **heterogeneity is the product**. Hooks make a pull protocol enforceable only because the layer sits beneath every vendor; vendor entry is survivable only for mixed-vendor teams; Conductor is avoidable only off the Mac-and-cloud path; and governance is sellable only when the lead needs one policy across several agents. A team that runs only Claude Code will eventually be served by Anthropic, so the single most important metric is not stars or seats but the share of workspaces running two or more agent vendors across two or more OSes. If that share stays low after launch, the market thesis is wrong, regardless of adoption.

The sequencing follows from this. Ship Claude Code and Codex adapters first, because they have the strongest hooks and the only real push channels, and use them to measure what no study has yet: how often hook-delivered claims prevent a conflict that rules files would have missed. That number is both the product's proof and its pitch. Publishing it, alongside an open claim and intent schema, turns a solo student's maturity gap into credibility, since the incumbents have every incentive not to measure coordination across tools they do not own.
